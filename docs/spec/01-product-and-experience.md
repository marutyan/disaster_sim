# 01. Product and Experience Specification

## 1. Product objective

本システムは、平時にユーザー自身が普段生活する地点で災害を疑似体験し、発災後の意思決定を体験的に学ぶ防災訓練Webアプリケーションである。

中心価値は、静的ハザード情報を表示することではなく、次の因果をユーザー自身の行動として体験させることにある。

> **どこにいるか → 何が起きるか → 何を知ることができるか → いつ動くか → どこを通るか → どこへ逃げるか → その判断が結果をどう変えるか**

### PRD-001

本システムは、発災前から安全確保または被災判定、振り返り、再挑戦までを一続きの時間軸として提供しなければならない。

### PRD-002

本システムは、単なる最短経路ナビゲーションではなく、避難開始時刻・経路・避難先・事前準備の違いが結果へ与える影響を学習できなければならない。

### PRD-003

本システムは平時の訓練用であり、実災害時の避難ナビゲーションとして使用されることを意図してはならない。

## 2. Non-goals

以下は製品目的に含めない。

- 地震発生日時の予知
- 個々の建物の実被害保証
- 個人の医学的予後予測
- 実災害時のリアルタイム最適避難ルート保証
- 公的警報・自治体判断の代替
- 写実的な破壊映像自体を目的とするエンターテインメント
- ハイスコア競争
- ユーザー位置情報収集自体を目的とするサービス

## 3. Audience

### 3.1 Initial audience

MVPでは一般住民を主対象とする。

前提知識は要求しない。ゲーム操作への習熟も要求しない。

### 3.2 Future audiences

コア設計は以下へ拡張可能でなければならない。

- 小中高生
- 大学生・社会人
- 学校
- 企業
- 自治体
- 防災教育担当者
- 研究用途

教育モードでは説明難易度・視覚表現強度を変更可能な設計とする。

## 4. Canonical user journey

標準フローは以下とする。

```text
Landing
  ↓
Training disclaimer / data explanation
  ↓
Location selection
  ↓
Scenario selection
  ↓
Player / companion / preparedness settings
  ↓
Short pre-check / tutorial
  ↓
~1 minute before event
  ↓
Earthquake onset
  ↓
Situational awareness
  ↓
Evacuation decision
  ↓
FPS / TPS / map movement
  ↓
Dynamic urban hazards
  ↓
Safe / injured / fatal-equivalent / undetermined outcome
  ↓
Map + timeline + 3D review
  ↓
Rewind / retry / compare
```

## 5. Location selection

### UX-LOC-001

開始地点は以下から選択可能とする。

- 地図クリック
- 住所検索
- ブラウザの現在地
- 保存地点

### UX-LOC-002

保存地点には `自宅`, `学校`, `職場` 等のユーザーラベルを付与できる。

### UX-LOC-003

住所Geocoderの結果が建物単位で十分でない場合、地図上のピン位置をユーザーが修正できなければならない。

### UX-LOC-004

住所文字列・自宅属性のクラウド保存を主要機能利用の必須条件にしてはならない。

## 6. Scenario configuration

ユーザーは以下を選択できる設計とする。

- 災害シナリオ
- 発災時刻
- 曜日
- 季節
- 天候
- 発災時の活動
- 人物プロフィール
- 同伴者
- 防災準備

### 6.1 Activity presets

例:

- 睡眠中
- 授業中
- 勤務中
- 買い物中
- 屋外移動中
- 自宅で通常生活中

### 6.2 Time and environment

任意時刻・曜日・季節・天候を設定可能にする。

これらは、根拠がある場合に以下へ影響可能とする。

- 明るさ
- 温度等の環境表現
- 人口分布
- 交通量
- NPC活動状態
- 停電時の視認性

根拠のない高精度な人口・交通量変化を公式値として扱わない。

## 7. Start timing

標準シナリオは発災約1分前から開始する。

開始前時間はシナリオごとに変更可能だが、通常利用で長い日常生活シミュレーションを要求しない。

発災前の1分は次の役割を持つ。

- 現在位置の把握
- 周辺環境の認識
- 同伴者の確認
- 室内状況の確認
- 「突然発生する」時間感覚の形成

## 8. Camera and movement modes

### UX-CAM-001

標準視点はFPSとする。

### UX-CAM-002

TPSへ任意に即時切替できなければならない。

### UX-CAM-003

地図モードへ任意に切替できなければならない。

### UX-CAM-004

FPS操作技能が避難結果を過度に支配してはならない。

地図モードでは地点指定による移動支援を提供できる。

ただし、正解経路を自動選択して避難判断を消してはならない。

## 9. Movement means

長期仕様では以下を扱う。

- 徒歩
- 自転車
- 自動車

MVPでは徒歩を必須とする。

自転車・自動車はドメインモデルとInterfaceを阻害しない設計にするが、MVP completion blockerとはしない。

移動手段は次の影響を受ける。

- 人物能力
- 荷物
- 坂道
- 夜間
- 負傷
- 混雑
- 冠水
- 道路閉塞
- 火災
- 公的避難方針

自動車を常に徒歩より優れた避難手段として扱ってはならない。

## 10. Player profiles

最低限、以下のプリセットを定義可能とする。

- 成人
- 子ども
- 高齢者
- 車椅子利用者
- 要配慮者
- カスタム

人物プロフィールは医学的診断を表すものではない。

### UX-PER-001

人物プロフィールは、移動能力・一部操作可能性・同伴者関係・避難時間等へ影響可能でなければならない。

## 11. Companion model

ユーザーは一人で避難するだけでなく、同伴者を持てる。

同伴者について以下の判断を行える設計とする。

- 声をかける
- 待つ
- 助ける
- 先に行く
- 別行動する

同伴者は単なる追従オブジェクトではなく、避難時間・移動速度・判断へ影響し得る。

## 12. Preparedness profile

ユーザーの普段の備えをプロフィールとして保持可能にする。

例:

- 家具固定
- 出口周辺の整理
- 非常持出袋
- 靴
- 懐中電灯
- モバイルバッテリー
- オフライン地図
- 感震ブレーカー

### UX-PREP-001

準備項目は単なるチェックリストではなく、根拠がある場合にSimulation Stateへ因果的な影響を与える。

例:

```text
家具固定
  → 家具転倒イベントの発生確率または危険範囲を低下

モバイルバッテリー
  → Device battery stateへ影響

感震ブレーカー
  → 対応する出火モデルへ影響
```

### UX-PREP-002

非常持出袋を取得するために引き返す等、準備品の存在が必ず正の結果のみを生む設計にしてはならない。

## 13. Time controls

ユーザーは以下を選択可能とする。

- Pause
- 1x
- 2x
- 5x
- 10x

### UX-TIME-001

時間倍率変更によって、同じRun Identityにおける主要確率イベントの結果が変わってはならない。

### UX-TIME-002

Pause中に、通常なら未来まで取得不能な情報を自動開示してはならない。

## 14. Information available during training

通常モードでは、その時点でユーザーが現実的に取得可能な情報を基本とする。

例:

- 緊急地震速報
- 津波警報等
- 自治体防災情報
- 周囲の目視情報
- スマートフォンで利用可能な情報

未来の津波位置・将来の道路閉塞を常時表示してはならない。

## 15. Training assistance mode

学習支援モードでは追加支援を許可する。

- 公的避難場所表示
- 危険区域表示
- ヒント
- 操作支援

支援量によって難易度を調整する。

`Easy / Normal / Hard` のようなゲーム難易度より、「どの情報・支援を開示するか」を明示する方針とする。

## 16. Hint system

### UX-HINT-001

安全判断そのものをLLMへ委ねてはならない。

ヒントは次の順で生成する。

```text
validated rule / official guidance
    ↓
decision content
    ↓
optional natural-language rendering
```

LLMを使用する場合は最終文章化に限定可能とする。

LLMが利用不能でも基本訓練は成立しなければならない。

## 17. Smartphone simulation

スマートフォンを万能情報端末として扱わない。

保持する状態例:

```text
battery
physical_connectivity
network_congestion
gps_available
offline_map_available
charging_available
```

以下を再現可能とする。

- 停電による充電不能
- 通信障害
- 回線混雑
- バッテリー枯渇
- GPS
- オフライン地図
- 緊急通知

## 18. Injury presentation

HP制を採用しない。

ユーザー向け状態は概ね以下とする。

- 無傷
- 軽傷
- 重傷
- 死亡相当

死亡相当時はSimulationを終了する。

軽傷・重傷で避難継続できた場合は、最終評価でその状態を明示する。

## 19. Visual severity

災害表現はリアル寄りとする。

対象:

- 強い揺れ
- 家具転倒
- ガラス破損
- 建物損傷
- 瓦礫
- 火災
- 津波
- 漂流物
- 停電した街

一方、以下を目的化しない。

- 過度な流血
- 遺体の詳細描写
- 苦痛を強調する残酷表現

教育目的に必要な因果が伝わることを優先する。

## 20. Evacuation destination behavior

ユーザーは任意地点へ移動できる。

公的な以下の地点は候補として表示可能とする。

- 指定緊急避難場所
- 津波避難ビル
- 高台
- その他公的避難地点

「指定場所に到着した = 必ず安全」としてはならない。

同様に、「任意地点で偶然助かった = 推奨行動」としてはならない。

## 21. Outcome representation

結果は単一スコアにしない。

最低限、次を別軸で評価する。

- 避難開始判断
- 情報確認
- 経路選択
- 到達地点
- 危険行動
- 所要時間
- 負傷
- 同伴者への対応
- 防災準備

### UX-OUT-001

結果論と判断の妥当性を分離する。

例:

> シミュレーション上は無事だったが、公的に指定された避難先ではなく、安全な判断として推奨できない。

## 22. Review experience

振り返りはMVPの中核機能とする。

以下を時間同期して確認可能にする。

- 地図
- タイムライン
- 簡易3Dリプレイ
- プレイヤー経路
- NPC
- 道路状態
- 災害状態
- 負傷地点
- 意思決定イベント
- 公的避難先
- 体験中には開示されていなかった危険情報

### UX-REV-001

振り返りでは「その時点で何を知り得たか」と「実際には周囲で何が起きていたか」を区別して表示する。

### UX-REV-002

ユーザー経路と、より安全だった可能性が高い候補経路を比較できる。

候補経路を唯一の正解として表示しない。

## 23. Retry and rewind

以下を可能にする。

- チェックポイントへ巻き戻す
- 手動保存地点へ戻る
- 同じseedで再挑戦
- seedを変更する
- 避難開始時刻を変更する
- 防災準備を変更する
- 人物条件を変更する

比較項目:

- 避難時間
- 経路
- 被災位置
- 負傷状態
- 安全性
- 判断イベント

## 24. Tutorial and learning flow

初回は操作チュートリアルを提供する。

災害種別ごとに短い説明を提供する。

標準教育フロー:

```text
短い事前確認
  → 体験
  → 振り返り
  → 再挑戦
```

防災知識クイズは任意とする。

## 25. Accessibility

設計初期から以下を考慮する。

- 字幕
- 色覚多様性
- UI拡大
- キーバインド変更
- Keyboard / Mouse
- Gamepad
- 画面揺れ軽減
- FOV調整
- モーションブラー調整
- 音量カテゴリ別調整
- FPSからTPS/地図への即時切替

## 26. Audio design

BGMより環境音・警報を重視する。

- 緊急速報
- 地震音
- 家具・ガラス
- 建物損傷
- 火災
- 水流
- サイレン
- NPC

可能な範囲で空間音響を採用する。

## 27. Language

初期UIは日本語とする。

文字列・教材コンテンツ・日時/単位表示はi18n可能な構造とし、将来の多言語化を妨げてはならない。

## 28. Account behavior

アカウントなしでMVP主要機能を完結できなければならない。

クラウド同期・複数端末同期が必要な場合のみログインを要求可能とする。

## 29. Sharing

MVPでは位置情報を含むReplay共有を実装しない。

将来共有する場合も、自宅等の識別につながる座標・ラベルを匿名化/削除する仕組みを前提とする。

## 30. Explicit UX prohibitions

以下を禁止する。

- HPバー
- ハイスコア中心の評価
- 正解経路の常時表示
- 未来情報の通常モード常時開示
- 画面上の精密値が公式値であるかのような誤認誘導
- 実災害時利用を促すUI
- ショック目的の残酷表現
- ゲーム操作技能のみで防災能力を評価する設計
